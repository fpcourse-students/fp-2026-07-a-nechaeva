# Как писать λ-домашки

## Термы

Файл состоит из определений и проверок. Определение — это имя, `:=` («обозначим», как на практике) и терм в одну строку:

```
plus := \n m. natElim n suc m   -- ответ дан
three := plus 1 2
divides3 := ...                 -- ответа пока нет
```

* `\n m. natElim n suc m` — абстракция с двумя параметрами, то же, что `\n. \m. natElim n suc m`; вместо `\` можно писать `λ`, вместо точки — `->`. Тело тянется вправо до конца строки или до закрывающей скобки.
* `natElim n suc m` — аппликация пробелом, левоассоциативная: это `((natElim n) suc) m`. Скобки нужны только для группировки: `plus 1 (plus 1 1)`.
* `1`, `2` — числа Чёрча ⌜1⌝ = `\s z. s z`, ⌜2⌝ = `\s z. s (s z)`; в интерпретаторе `three` редуцируется к ⌜3⌝.
* `three := plus 1 2` — в правой части можно использовать любые имена, определённые выше: с лекции и свои.
* `...` — дырка: сюда пишется ответ. Дырка может стоять и внутри терма, пока он не дописан.
* `-- текст` — комментарий до конца строки.

Определения с лекции и практики стоят в начале `hw.lam`, до первой задачи, менять их не нужно. Имена — буквы, цифры, `_` и штрих: `K'` — это K* с лекции. Свободные переменные можно использовать только те, что перечислены в строке `vars` в начале файла; любое другое незнакомое имя проверялка считает опечаткой.

## Интерпретатор

`make repl` загружает `src/hw.lam` и открывает интерпретатор; это сокращение для `cabal run -v0 lambda -- load src/hw.lam`. Прогулка по нему с примерами и выводом каждой команды — в [TUTORIAL.md](TUTORIAL.md). Без файла (`cabal run -v0 lambda -- load`) открывается пустая сессия чистого λ-исчисления, где все имена нужно определять самому; `--language typed` даёт такую же сессию с литералами и примитивами.

Если введёте терм, он проредуцируется до нормальной формы.

Дополнительные команды:

* `:follow терм` показывает каждый шаг, `:step` — один шаг;
* `:explain терм` рисует дерево терма;
* `:decode терм` печатает результат как число, пару или список. Читает он нормальную форму буквально: `false` и ⌜0⌝ для него одно и то же, а `\z. z` он не покажет как ⌜1⌝, хотя проверка `expect` считает такие термы равными (с точностью до η);
* `:type терм` выводит наиболее общий тип;
* `:r` перечитывает файл после правок, не выходя из интерпретатора;
* `:help` — всё остальное.

## Проверки

Проверки в файле — открытые тесты, их можно и нужно читать:

* `expect левое = правое` вычисляет обе стороны и сравнивает их с точностью до α и η;
* `nf терм = ответ` — то же сравнение, но ответ должен быть нормальной формой, а не любым равным термом: числом, `true`, термом без редексов или данными вроде `cons 4 (cons 9 nil)`. Ответ `pred 3` вместо `2` проверка не примет и скажет, что в нём ещё можно вычислить;
* `chain name = ...` — цепочка редукций по шагу на строку: `~b~>` один β-шаг, `~K~>` раскрыто или свёрнуто одно вхождение имени `K` (как ⇝<sub>K</sub> на практике), `=a=` переименование связанной переменной, `~eta~>` один η-шаг (`\x. M x` в `M`, если `x` не свободна в `M`, или обратно), `~s~>` выполнена подстановка `[x |-> N] M`, `~~>` до трёх шагов сразу. Если проверялка не согласна с переходом, она скажет, между какими строками и какие шаги были возможны;
* `free`, `rename`, `minimal`, `check`, `type`, `church`, `inhabit`, `family` объяснены в условиях тех задач, где встречаются.

Задача считается TODO, пока все её проверки упираются в дырку; PARTIAL — когда часть проверок прошла; DONE — когда все. Полное описание формата — в [FORMAT.md](FORMAT.md).
