# Fp. Hw07. Свёртки

Эта домашка продолжает практику 7: свёртки и развёртки, полугруппы, моноиды и `Foldable`. Задания находятся в `src/Level1.hs`, `src/Level2.hs` и `src/Level3.hs`; условие каждой задачи — перед её кодом. Данный код для чтения и нормализации текста находится в `src/Examples.hs`.

В `app/Main.hs` находится готовое приложение, вызывающее ваши решения, с ASCII-заставками из исходной домашки. В `text/` лежат «Алиса в Стране чудес» и семь книг о Гарри Поттере; тексты перенесены без изменений. Код ввода-вывода дан готовым; до решения соответствующих задач приложение встретит их заглушки.

После задач 1.6 и 2.6 посмотрите частоты слов в «Алисе»:

```sh
make run ARGS=wc < text/alice.txt
```

Можно передать имя файла аргументом: `make run ARGS='wc text/alice.txt'`. После задач 3.2 и 3.3 попробуйте поиск по семи книгам: индекс строится один раз, затем приложение отвечает на каждый запрос.

```sh
make run ARGS='find hermione basilisk lol'
```

Для своих файлов используйте `make run ARGS='find-in слово файл1.txt файл2.txt'`. `make run ARGS=--help` показывает все варианты запуска.

Сначала предскажите результаты трёх выражений и найдите контрпример к вычитанию расходов. Затем закончите поиск через `foldr` и подсчёт через `foldMap`, самостоятельно напишите полный инстанс `Foldable` дерева и цепочку подсчёта слов. Базовые ветки даны в упражнениях с пропусками; отдельные проверки поэтому могут проходить ещё до решения. Для DONE должны пройти все проверки задачи.

Строки вида `todoImpl ''Foldable ''Tree` создают временные инстансы, чтобы проект и тесты собирались до решения. Удалите такую строку и на её месте напишите инстанс целиком: его заголовок, необходимые ограничения и методы. Выберите минимально необходимый набор методов; методы по умолчанию можно не переопределять. Разбираться в устройстве `todoImpl` не требуется. Обычные заглушки `todo` заменяются вашим кодом.

| Уровень | Задачи |
|---|---|
| 1, обязательный: 1.1–1.6 | Предсказание; контрпример; `elem'`; `countMatching`; `Foldable Tree`; `wordCount` |
| 2, к сессии: 2.1–2.7 | Специализированные свёртки; `map` через `unfoldr`; операции, объединение и обход словаря; форматирование частот; значения `Right` |
| 3, челлендж: 3.1–3.3 | BFS дерева с соседями; инвертированный индекс; поиск релевантного документа |

Для первой задачи запишите ответы до запуска выражений. В задаче с контрпримером не исправляйте выданную функцию: тест проверяет ваш вход. Законы `Semigroup`, `Monoid` и `Foldable` — в лекции 7, слайды 19, 23 и 36; имена законов в тестах помогают найти нарушенное требование. Законы не определяют единственный порядок обхода: дополнительно соблюдайте порядок, заданный условием. В `Tree` это DFS, в дереве с соседями — BFS. Объединение `MyMap` берёт значение из левого словаря при совпадении ключей; повторные вставки, напротив, сохраняют последнюю запись.

Задачи «Разное» намеренно не называют метод: выберите подходящий инструмент сами. В 2.7 пригодятся конструкторы и сопоставление с образцом из практики 5. Перемешивание может ощущаться труднее, чем серия однотипных упражнений; это тренировка выбора способа решения для очной сессии.

Тесты 2.4 и 2.5 получают готовые словари и не требуют завершения 2.3. Тесты 2.6 получают готовые частоты, а тесты 3.3 — готовый индекс. Задача 3.2 использует `wordCount` из 1.6. Ограничения «через foldr», «через unfoldr» и перечень разрешённых функций в 2.1 проверяются на ревью и очной сессии; автотесты проверяют значения, законы и ленивость.

В интерпретаторе (`make repl`) команда `:t` настроена так, что числам сразу выбирается тип по умолчанию: `:t 1` отвечает `1 :: Integer`. Настройка лежит в файле `.ghci`.

## Установка

Нужны компилятор GHC 9.10.3, система сборки cabal и `make`; для домашек на Haskell (с четвёртой недели) ещё линтер hlint. Компилятор и cabal ставятся через [ghcup](https://www.haskell.org/ghcup/) одной командой.

Linux и macOS:

```sh
curl --proto '=https' --tlsv1.2 -sSf https://get-ghcup.haskell.org | sh
```

На Linux компилятору нужны системные библиотеки, и без них установка или первая сборка падает с ошибкой про `gmp` или `tinfo`. На Ubuntu и Debian поставьте их заранее:

```sh
sudo apt install build-essential curl libffi-dev libgmp-dev libncurses-dev pkg-config
```

На старых версиях Ubuntu дополнительно нужен `libtinfo-dev`. Fedora: `sudo dnf install gcc gcc-c++ gmp gmp-devel make ncurses ncurses-devel xz perl`; Arch и Manjaro: `sudo pacman -S --needed base-devel gmp ncurses`; openSUSE: `sudo zypper install gcc gcc-c++ gmp-devel make ncurses-devel xz perl`. Полный список — на [странице установки ghcup](https://www.haskell.org/ghcup/install/#system-requirements). Если компилятор уже стоит, а первая сборка домашки падает с упоминанием `terminfo` или `tinfo`, не хватает именно `ncurses-devel` (`libncurses-dev`): его требует интерпретатор λ-термов.

Windows (PowerShell, команда с сайта ghcup):

```powershell
Set-ExecutionPolicy Bypass -Scope Process -Force;[System.Net.ServicePointManager]::SecurityProtocol = [System.Net.ServicePointManager]::SecurityProtocol -bor 3072; try { & ([ScriptBlock]::Create((Invoke-WebRequest https://www.haskell.org/ghcup/sh/bootstrap-haskell.ps1 -UseBasicParsing))) -Interactive -DisableCurl } catch { Write-Error $_ }
```

Установщик задаст вопросы: соглашайтесь поставить GHC и cabal, HLS (Haskell Language Server) — по желанию, он даёт подсказки в редакторе. После установки откройте новый терминал и выберите версии по умолчанию, по одной команде на строку (в PowerShell `&&` не работает):

```sh
ghcup install ghc 9.10.3 --set
ghcup install cabal recommended --set
```

Версия компилятора зафиксирована в `cabal.project`, поэтому другой компилятор сборка не примет. Вторая команда нужна, если `cabal` не находится или ghcup просит выбрать версию cabal по умолчанию: установщик иногда ставит cabal, но не назначает его текущим.

В домашках по λ-исчислению линтера нет: там нет кода на Haskell, и `make check` его не запускает. В домашках на Haskell линтер подсказывает, как упростить код. На статус задач его подсказки не влияют, но `make check` показывает их каждый раз. Быстрее всего взять готовый бинарник из [релизов hlint](https://github.com/ndmitchell/hlint/releases) (есть для Linux, macOS и Windows) и положить его в `PATH`; пакетный менеджер вашей системы тоже подойдёт. `cabal install hlint` работает, но собирает линтер из исходников долго. Если hlint выдаёт ошибки на выданный вам код, обновите его (нужна версия не ниже 3.4.1).

Все команды домашки собраны в `Makefile`, `make` без аргументов печатает их список. На Linux и macOS `make` уже есть или ставится пакетным менеджером; на Windows он есть в оболочке MSYS2, которую устанавливает ghcup (`pacman -S make`).

## Уровни задач

Уровня три, и номер задачи начинается с её уровня:

* `1.x` — обязательные задачи: домашка сдана, когда все они в статусе DONE;
* `2.x` — задачи, к которым стоит вернуться до очной сессии;
* `3.x` — челлендж для тех, кому мало.

Задачи лежат в `src/`: в домашках по λ-исчислению — один файл `src/hw.lam`, в домашках на Haskell — модули по уровням `src/Level1.hs`, `src/Level2.hs`, `src/Level3.hs`. Список задач с подписями — в файле `TASKS` в корне репозитория; некоторые задачи взаимозаменяемы: правило `rule any k of: ...` там означает, что из перечисленных достаточно закрыть любые k.

У каждой задачи после прогона тестов четыре возможных статуса: DONE (все тесты прошли), PARTIAL (часть прошла), FAILED (ничего не прошло) и TODO (вы к ней не приступали: на месте решения всё ещё заглушка `todo` или дырка `...`). Баллов за задачи нет: важно только, закрыт ли уровень 1. Ровно это и означает цвет CI: зелёный — уровень 1 закрыт.

## Порядок работы

1. Клонируйте свой репозиторий: `git clone git@github.com:...`.
2. Соберите проект: `make build`. Первый раз это долго, потому что собираются все зависимости.
3. Выполняйте задания в `src/`.
4. Загружайте код в интерпретатор: `make repl`. Для Haskell это GHCi со всеми уровнями домашки в области видимости, для λ-исчисления — интерпретатор λ-термов с `src/hw.lam` (прогулка по нему — `lambda-engine/TUTORIAL.md`).
    * После правок перезагружайте интерпретатор командой `:r`.
    * Проверяйте решения вручную.
5. Запускайте `make check`: тесты всех заданий (в Haskell-домашках перед ними линтер). В конце — таблица со статусом каждой задачи и вердикт по уровню 1.
6. Пока возитесь с одной задачей, тестируйте только её: `make check ONLY="1.1 1.2"`.
7. Отправляйте на автоматическую проверку: `make submit`.

## Использование AI

- Модель умеет решать многие задачи этой домашки. Самостоятельная попытка нужна, чтобы вы могли воспроизвести рассуждение на очной сессии и экзамене без интернета.
- Можно просить объяснить сообщение GHC или конструкцию, предложить тесты и контрпримеры, обсудить ваше решение.
- Не сдавайте код, который не можете объяснить. Ничего не должно быть магией, в этом суть курса.
- Если пользовались AI, оставьте короткий комментарий рядом с решением: чем и для чего пользовались. Это материал для обсуждения, а не инструмент наказания.
